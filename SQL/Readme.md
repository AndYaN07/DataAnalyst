Proyecto SQL - Máster Data & Analytics

Descripción
Este proyecto consiste en la exploración y manipulación de una base de datos relacional PostgreSQL la cual llamamos "tiendaMaster", proporcionada por la plataforma PROMETEO. Se realizaron consultas SQL para practicar el manejo de datos, relaciones entre tablas, subconsultas, vistas y estructuras temporales, con el objetivo de entender y extraer información relevante para análisis de datos.

Herramientas utilizadas
1. DBeaver: Entorno gráfico para conectarse y gestionar la base de datos PostgreSQL.
2. PostgreSQL: Sistema de gestión de bases de datos relacional.
3. dbdiagram.io: Para crear diagramas ER de la base de datos.
4. GitHub: Control de versiones y entrega del proyecto.

Pasos para la configuración y ejecución
1. Actualización y apertura de DBeaver, conexión a PostgreSQL.
2. Descarga de la base de datos desde la plataforma PROMETEO.
3. Creación de la base de datos con el nombre tiendaMaster en PostgreSQL.
4. Ejecución del script SQL descargado para la creación de tablas y carga de datos.
5. Análisis y diagramación del esquema de la base de datos mediante dbdiagram.io (https://dbdiagram.io/d/68618094f413ba350867889d) para comprensión profunda.
6. Realización de consultas SQL para cubrir los requerimientos del proyecto, guardando cada consulta ordenadamente en el archivo "entrega.SQL".

Contenidos y enfoque de las consultas
1. Consultas con una sola tabla para familiarización con los datos.
2. Consultas que manejan relaciones y joins entre múltiples tablas.
3. Uso de subconsultas para resolver problemas complejos.
4. Creación y manejo de vistas para consultas reutilizables.
5. Uso de tablas temporales para almacenar resultados intermedios.
6. Aplicación de funciones agregadas y cláusulas de agrupamiento.
7. Ordenación y filtrado de resultados para mejorar la presentación.
8. Práctica con distintas cláusulas WHERE, HAVING, y operadores lógicos.

Buenas prácticas aplicadas
1. Uso constante de alias para tablas y columnas para mejorar la legibilidad.
2. Comentarios en las consultas para explicar la lógica implementada.
3. Consistencia en la indentación y formato SQL para facilitar la lectura.
4. Uso de nombres claros y descriptivos para columnas calculadas o agregadas.
5. Manejo adecuado de NULLs y condiciones en filtros para evitar errores.
6. Control de versiones con commits significativos en GitHub.

Entrega y control de versiones
El proyecto está versionado y alojado en un repositorio de GitHub, donde se han subido de forma ordenada y documentada las consultas, scripts y documentos adicionales. Esto asegura la trazabilidad y facilita futuras mejoras o revisiones.
